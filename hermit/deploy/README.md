# `deploy/` — operator guide

Everything needed to turn a blank SD card and a box of parts into a running
HERMIT device. Read `../docs/BRINGUP.md` alongside this: that is the hardware
checklist, this is the software deployment.

---

## What each file is

| File | What it is | Where it ends up |
|---|---|---|
| `provision.sh` | Idempotent root script that prepares a fresh Raspberry Pi OS Lite 64-bit install: user, directories, packages, zram, boot config, service trimming, CPU governor, NTP, journald, ALSA, systemd units, secrets template. Safe to re-run any time. | run on the Pi |
| `asound.conf` | The ALSA configuration. Defines the whole signal chain and the named PCMs the daemon opens. **Has an operator adjustment block at the top that you must edit once, after step 2 of bring-up.** | `/etc/asound.conf` |
| `hermit.service` | The daemon. `Type=notify`, 30 s watchdog, `Restart=always`, hardened, memory-capped for a 1 GB box. | `/etc/systemd/system/` |
| `hermit-consolidate.service` | One-shot nightly memory consolidation (`hermit consolidate`). | `/etc/systemd/system/` |
| `hermit-consolidate.timer` | Fires the above daily at 04:00 local, `Persistent=true`. | `/etc/systemd/system/` |
| `Cross.toml` | `cross` configuration for building the aarch64 binary on your dev machine. Installs ALSA headers and pkg-config into the build image. | dev machine, at the workspace root |
| `README.md` | This file. | — |

Two more units are **generated by `provision.sh`** rather than living here,
because they are pure deployment artifacts with nothing worth version
controlling: `hermit-mpv.service` (internet radio sidecar) and
`hermit-librespot.service` (Spotify Connect). Both play to ALSA `default`,
which is the volume-limited mono chain through the Flex.

## Order of operations for a fresh build

Do these in order. Steps 1 and 2 are the hardware; 3–6 are the software.

### 1. Flash the reSpeaker firmware — `../scripts/flash_notes.md`

**Nothing else works until this is done.** The "with XIAO ESP32S3" SKU ships
with I2S firmware and is invisible as a USB audio device. Flash the **USB
2-channel linear** variant via Safe Mode + `dfu-util`.

### 2. Bring-up steps 1–2 — `../docs/BRINGUP.md`

Confirm enumeration, then run `--dump-hw-params` and write down the card's
short name and native sample rate. Edit the adjustment block at the top of
`asound.conf` (both the copy in this repo and, later, `/etc/asound.conf`).

### 3. Provision the Pi

```bash
# from your dev machine
rsync -av --delete hermit/deploy/ hermit/scripts/ pi@hermit.local:/tmp/hermit-deploy/

ssh pi@hermit.local
sudo bash /tmp/hermit-deploy/provision.sh
sudo reboot          # the first run changes boot config; it will tell you
sudo bash /tmp/hermit-deploy/provision.sh   # second run sets the ALSA mixer
```

The second run matters: on the first pass the card may not have enumerated in
its final order yet, so the mixer step is skipped. Re-running converges it. The
script prints a summary of everything it changed and everything still left for
you to do.

Then finish bring-up steps 3–6 (capture, playback, AEC, TTFT, thermals) and
sign off the gate before continuing.

### 4. Cross-compile on the dev machine

**Never compile on the Pi.** 1 GB of RAM, LTO and a bundled SQLite amalgamation
do not end well, and it burns SD write cycles for nothing.

```bash
# once
rustup target add aarch64-unknown-linux-gnu
cargo install cross --git https://github.com/cross-rs/cross
# Docker (or Podman with CROSS_CONTAINER_ENGINE=podman) must be running.

cd hermit
ln -sf deploy/Cross.toml Cross.toml     # cross looks for it next to Cargo.toml

export PKG_CONFIG_ALLOW_CROSS=1         # alsa-sys needs this when cross-compiling
cross build --release --target aarch64-unknown-linux-gnu --features pi
```

`--features pi` is **required**: it enables `alsa-audio`, `wake-porcupine` and
`systemd` (sd_notify). Without it you get a binary that builds cleanly and then
never sends `READY=1`, so systemd kills the unit at the start timeout.

Result: `target/aarch64-unknown-linux-gnu/release/hermit`

Sanity-check it before shipping:

```bash
file target/aarch64-unknown-linux-gnu/release/hermit   # ELF 64-bit LSB, ARM aarch64
ls -lh target/aarch64-unknown-linux-gnu/release/hermit
```

### 5. Copy the binary and the config tree over

```bash
PI=pi@hermit.local

# Binary — into a temp path first, then move into place as root.
scp target/aarch64-unknown-linux-gnu/release/hermit "$PI":/tmp/hermit.new

# Data files: hermit.toml, prompts/, skills/, identity.md, core.md, stations.toml
rsync -av --delete config/ "$PI":/tmp/hermit-config/

ssh "$PI" '
  sudo install -o root -g hermit -m 0755 /tmp/hermit.new /opt/hermit/bin/hermit &&
  sudo rsync -a --delete /tmp/hermit-config/ /opt/hermit/config/ &&
  sudo chown -R root:hermit /opt/hermit/config &&
  sudo chmod -R go-w /opt/hermit/config &&
  rm -f /tmp/hermit.new && rm -rf /tmp/hermit-config
'
```

`/opt/hermit` is deliberately **root-owned and read-only to the daemon** — the
unit sets `ProtectSystem=strict`, so the daemon cannot rewrite its own prompts
or replace its own binary even if it wanted to.

**Porcupine runtime files.** The wake-word engine's native shared library, its
model (`.pv`) and your keyword (`.ppn`) are resolved at runtime, not linked
into the binary. They must be copied to the Pi too — put them under
`/opt/hermit/config/` and point `hermit.toml` at them.

### 6. Fill in the secrets, then start

`provision.sh` created `/etc/hermit/hermit.env` as an empty 0600 template owned
by `hermit`. It never overwrites an existing one, and no secret ever goes in
the repo.

```bash
ssh pi@hermit.local
sudo -e /etc/hermit/hermit.env      # or: sudo nano /etc/hermit/hermit.env
```

Fill in: `CEREBRAS_API_KEY`, `PARALLEL_API_KEY`, `FIRECRAWL_API_KEY`,
`CARTESIA_API_KEY`, `ELEVENLABS_API_KEY`, `DEEPGRAM_API_KEY`,
`PICOVOICE_ACCESS_KEY`, `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`,
`SPOTIFY_REFRESH_TOKEN`.

Format is `KEY=value` — no quotes, no `export`, no spaces around the `=`.
systemd is not a shell; quotes end up inside the value.

```bash
sudo systemctl start hermit
systemctl status hermit
journalctl -u hermit -f
```

## Updating an already-deployed device

### Binary only

```bash
cd hermit
cross build --release --target aarch64-unknown-linux-gnu --features pi
scp target/aarch64-unknown-linux-gnu/release/hermit pi@hermit.local:/tmp/hermit.new
ssh pi@hermit.local '
  sudo install -o root -g hermit -m 0755 /tmp/hermit.new /opt/hermit/bin/hermit &&
  sudo systemctl restart hermit &&
  rm -f /tmp/hermit.new
'
```

`install` writes to a new inode and renames, so it works even while the old
binary is executing.

### Config only

```bash
rsync -av --delete hermit/config/ pi@hermit.local:/tmp/hermit-config/
ssh pi@hermit.local '
  sudo rsync -a --delete /tmp/hermit-config/ /opt/hermit/config/ &&
  sudo chown -R root:hermit /opt/hermit/config &&
  sudo systemctl restart hermit
'
```

### Units, ALSA config or provisioning logic

Re-run `provision.sh`. It is idempotent: it diffs before writing, only reports
what actually changed, and never touches an existing `hermit.env`.

```bash
rsync -av hermit/deploy/ pi@hermit.local:/tmp/hermit-deploy/
ssh pi@hermit.local 'sudo bash /tmp/hermit-deploy/provision.sh'
```

## Day-to-day operations

```bash
systemctl status hermit                 # state, watchdog, memory against MemoryMax
journalctl -u hermit -f                 # follow (journal is volatile: RAM only)
journalctl -u hermit -b                 # this boot
systemctl restart hermit

systemctl list-timers hermit-consolidate.timer    # when does the 04:00 job next run?
systemctl start hermit-consolidate                # run consolidation now, by hand
journalctl -u hermit-consolidate -n 100           # what did last night's pass do?

systemctl status hermit-mpv hermit-librespot      # sidecars

aplay -l ; arecord -l                   # the Flex must be the ONLY card
alsamixer -c <card>                     # levels; ceiling lives in asound.conf
sudo alsactl store                      # persist mixer changes across reboot
speaker-test -D hermit_out -c 2 -t sine -l 1

vcgencmd measure_temp                   # thermals
vcgencmd get_throttled                  # 0x0 = never throttled, never undervolted

sqlite3 /var/lib/hermit/hermit.db '.tables'
```

**The journal is volatile** — `provision.sh` sets `Storage=volatile` so logs
live in a 32 MB tmpfs and are gone after a reboot. That is deliberate SD-card
protection. Anything worth keeping goes into SQLite or off-box.

## Named ALSA PCMs

Defined in `asound.conf`. The daemon and the sidecars open these **by name** —
do not rename them without changing `hermit.toml` and the generated sidecar
units together.

| PCM | Direction | What it is |
|---|---|---|
| `hermit_out` | playback | plug → softvol (**-2.5 dBFS ceiling**) → stereo-to-mono route → dmix → Flex. The daemon's `audio.playback_pcm`. |
| `hermit_in` | capture | plug → route (card channel **0**, the XVF3800's processed mono voice) → dsnoop → Flex. The daemon's `audio.capture_pcm`. |
| `capture_ref` | capture | Card channel **1**, the AEC reference. Bring-up and debugging only; nothing at runtime uses it. |
| `hermit_raw` | playback | Same as `hermit_out` **without** the softvol ceiling. Measurement only — it can exceed the speaker's 3 W rating. |
| `default` | both | `asym`: playback `hermit_out`, capture `hermit_in`. This is why mpv, librespot, `aplay` and `speaker-test` need no ALSA flags. |

---

## Things that are locked, and why

- **The Flex is the only sound card.** Mic capture and every byte of playback
  go through it so the XVF3800's hardware AEC always has a loopback reference.
  That is what makes barge-in work — the wake word is heard over music and TTS.
  Do not use the Pi's 3.5 mm jack, do not add a DAC or amp, do not turn the
  ESP32 into a Wi-Fi audio satellite.
- **The softvol ceiling stays at -2.5 dBFS.** The core board's amp is rated
  10 W into 4 Ω, so roughly 5 W into the 8 Ω FIT0502, which is rated 3 W.
  `sqrt(3/5) = 0.775` of full scale is -2.2 dBFS; -2.5 gives margin. Raising it
  cooks the voice coil.
- **Everything is downmixed to mono.** There is one speaker.
- **Nothing is compiled on the Pi.** No Rust toolchain, no Docker, no build
  tools. Cross-compile and copy.
- **This is a 16 kHz voice-grade pipeline into a 3 W mono driver.** Fine for
  speech, news and casual music. Not hi-fi, and not to be "fixed" by changing
  the topology.

## AirPlay (optional, off by default)

`shairport-sync` turns the device into an AirPlay 2 receiver. It is **not**
installed or enabled by `provision.sh`.

```bash
sudo apt-get install -y shairport-sync
# set the ALSA output device to "default" in /etc/shairport-sync.conf
sudo systemctl enable --now shairport-sync
```

Two things to be clear about before enabling it:

1. **AirPlay is the only Apple Music path on Linux.** There is no Apple Music
   client for Linux and no API that lets a third party start Apple Music
   playback.
2. **The agent cannot drive it.** AirPlay is human-initiated: someone picks the
   device from their phone or Mac and HERMIT is simply a speaker for that
   stream. You cannot ask HERMIT to play an Apple Music track. Spotify (via
   librespot + the Web API) and internet radio (via mpv) are the paths the
   agent can actually control.

It is off by default because it is another always-on network listener for a
feature the agent cannot use.
